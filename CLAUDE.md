# Stoa

Offline PWA for tracking time on goals. See `README.md` for features, sign-in and the sheet layout.

## Layout

- `src/types.ts` and `TABS` in `src/sheets.ts`: the data contract (goals, sub-goals, results, result checks, plan, sessions) and the sheet layout. They match the Stoa page in the second brain and the check-in routine in the vault's `CLAUDE.md`. Change all three together. A sub-goal is a `Habit` in code and a row of the `habits` tab. New columns go at the end of a tab's list in `TABS`; opening a sheet appends them to its header row.
- `src/time.ts`, `src/stats.ts`, `src/results.ts`, `src/today.ts`, `src/logs.ts`, `src/quickInput.ts`, `src/overlap.ts`: pure logic (midnight split, goal stats, time per week/month/year, automatic results and the done list, minutes since the last check, Today's cards: order, drop place, sub-goals to add, the one-timer rule and time today; day of an entry, the Log's week pages, slugs; the Log's quick input line read into a session; overlapping sessions and keep both, trim or replace). They are covered by `test/`.
- `src/palette.ts`: the eight goal colours (a goal stores the key), the colour for a goal without one or a new goal, and contrast helpers; `test/palette.test.ts` checks contrast against the chart surfaces and text.
- `src/googleAuth.ts`: Google Identity Services token client, loaded on demand. The access token stays in memory; `AuthError` means the user must sign in.
- `src/sheets.ts`, `src/sync.ts`: Drive and Sheets REST client (find or create the sheet and its tabs and header columns, read tabs, rewrite tabs), row mapping, roll-up and restore. The tests use a fake Drive and Sheets API behind a fake fetch.
- `src/db.ts`: IndexedDB store. The Log reads sessions by day range (`entriesBetween`, `latestDayBefore`), never all at once; a deleted session can be put back as it was (`restoreEntry`). Every session or result check change marks its day dirty; roll-up rewrites the session rows of a dirty day in `logs` and its `result_checks` rows from the phone's copy (old counter rows stay). Entries and checks carry `uid`, their row id in the sheet. A plan the phone reorders or extends is marked dirty and replaces its date's `plans` rows. Results come from the check-in; the phone's renames and archiving are merged onto the sheet's rows by id.
- `src/state.tsx`: React app state and all actions (timer start, pause and start change, still-going check, today's card order and added sub-goals, checking and unchecking results, sync, log and config edits) in `useStoaState`, shared through `StoaProvider` and read with `useStoa()`. Components hold only form and view state.
- `src/App.tsx` and `src/components/Nav.tsx`: the URL hash (`useHashRoute.ts`) picks a tab: Today, Time, Goals, Results, Log; Settings opens from the gear in the Header. A timer shows only on its Today card.
- `src/screens/`: one component per tab, in the file of its name (Today, Time, Goals, Results, Log, Settings), plus SessionForm (Log's add and edit form; it also opens filled from quick input). Log loads a week per page as the list end scrolls into view, and has the quick input and each session's menu (long press or "…": edit, delete with Undo). Quick input and SessionForm both check overlaps before saving (`OverlapWarning`). Results is the only place where results are checked and unchecked: open results, then the done list (7 days after each entry's day), each grouped by goal and sub-goal. A manual result is open until it has any standing check, whatever the day; "Add another" on a done entry records a further check, and each check is unchecked by its uid. Time shows the stacked chart of `src/components/TimeChart.tsx` (inline SVG, bars selected by tap). Goals is the goal list (cards, long-press menu) and, for `#/goals/<id>`, `GoalDetail.tsx` (chart, time per sub-goal with automatic-result totals, archived sub-goals); goals and sub-goals are never added in the app, only renamed, recoloured and archived. Fill a tab in its own file; App and Nav need no change. `src/components/`: Nav, Header (sync badge and Settings gear), StillGoingDialog, Toast, HabitSelect, OverlapWarning (reads the saved sessions near a new one and offers keep both, trim, replace), BarChart (small stacked SVG bar chart), ItemMenu (rename, colour and archive sheet).
- `src/format.ts`: display helpers (names by id, active goals, datetime-local values, "last time spent").
- `test/TodayScreen.test.tsx`, `test/ResultsScreen.test.tsx`, `test/LogScreen.test.tsx`: component checks in jsdom, rendering a tab inside `StoaProvider` over an in-memory store and tapping through it; the Results file also calls the result actions directly, and the Log check confirms that editing an old day's session changes its automatic result and marks that day dirty.
- `sw/sw.js`: service worker template; the Vite plugin in `vite.config.ts` fills in the built file list.

## Rules

- The app improves continuously; there is no frozen scope. Accounts are Google sign-in with one sheet per user in their own Drive, nothing more. Forgotten-timer reminders are out for now (the still-going check on reopen stays).
- No tokens, secrets or personal data in this repo (the OAuth client id is public). The access token lives in memory only, never in IndexedDB; personal data lives in each user's sheet.
- The CSP in `vite.config.ts` allows only Google sign-in and the Drive and Sheets APIs; widen it only for a call the app really makes.
- Run `npm test` and `npm run build` before committing.
